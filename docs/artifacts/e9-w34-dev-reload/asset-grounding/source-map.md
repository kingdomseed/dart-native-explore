## Key concepts

### Authored references are specific schema fields

`AssetRef` is a source-path key, documented as relative to the owning package root. It is not a universal URI loader. The schema's actual fields decide what can be resolved. [scene property_value.dart:5](/Users/jasonholt/.pub-cache/hosted/pub.dev/scene-0.3.0/lib/src/property_value.dart:5).

| Authored field | Parsed owner | What it actually names | dart3d path and limit |
| --- | --- | --- | --- |
| `resources[tex].kind = texture`, `ref` | `TextureResource.asset` | External encoded image asset key | Both natives read packaged assets. No Dart texture-resolver parameter exists on `loadDocument` or `applyDiff`. |
| Texture `payload` | `TextureResource.payload` | Local payload ID | Bytes must already be attached to `PayloadSpec.bytes`, or arrive later through existing native channels. |
| Geometry `vertices`, `indices`, `morphTargets.deltas` | `GeometryResource` and `MorphTargetsSpec` | Local payload IDs | No geometry `ref`, `uri`, OBJ path, or arbitrary mesh-file field. Procedural geometry carries parameters, not external bytes. |

## How it works

### Parser, preparation, controller, native input

The authored-text path is `readFsceneLogged` → `readFsceneWithExtensions` → upstream JSONC/migration/document decode → optional caller preparation → `loadDocument` initially or `diffScene(controller.document, next)` plus `applyDiff` subsequently. The extension-aware reader preserves dart3d views, procedural resources, and property animations. [doc_layer.dart:87](/Users/jasonholt/.t3/worktrees/dart-native-explore/t3-c1e3ac06/dart3d/lib/src/doc_layer.dart:87), [diff_apply.dart:589](/Users/jasonholt/.t3/worktrees/dart-native-explore/t3-c1e3ac06/dart3d/lib/src/diff_apply.dart:589).

`loadDocument` resolves only its optional LUT callback, encodes the manifest, makes `doc` the accepted controller document, sends `loadScene`, then sends each non-null payload's raw bytes. `loadFscene` adds no file resolution. `applyDiff` likewise accepts an optional LUT callback, rediffs payloads/resources, stores `newDoc`, and sends one ordered command batch. [scene_controller.dart:268](/Users/jasonholt/.t3/worktrees/dart-native-explore/t3-c1e3ac06/dart3d/lib/src/scene_controller.dart:268), [loadFscene:321](/Users/jasonholt/.t3/worktrees/dart-native-explore/t3-c1e3ac06/dart3d/lib/src/scene_controller.dart:321), [applyDiff:516](/Users/jasonholt/.t3/worktrees/dart-native-explore/t3-c1e3ac06/dart3d/lib/src/scene_controller.dart:516).

The native input stays PluginMutation. Initial payload frames are `[8-byte LocalId][raw bytes]`; incremental `upsertPayload` is an existing command containing base64 plus its descriptor. These are the library-to-native transport, distinct from the host-to-app WebSocket. [protocol.dart:313](/Users/jasonholt/.t3/worktrees/dart-native-explore/t3-c1e3ac06/dart3d/lib/src/protocol.dart:313), [diff_apply.dart:75](/Users/jasonholt/.t3/worktrees/dart-native-explore/t3-c1e3ac06/dart3d/lib/src/diff_apply.dart:75). The vendor guide confirms the widget/NativeElement/provider mutation contract, with no Flutter MethodChannel assumption. [plugin_development.md:17](/Users/jasonholt/repos/dart-native-explore/dartnative/docs/plugin_development.md:17).

### Same-ID diffs and native consumers

`diffCommands` compares each new payload byte by byte, plus encoding, layout, format, width, height, and length. Null bytes skip sending. Byte changes produce `upsertPayload` with the existing ID and fresh descriptor. Geometry payload changes mark geometry resources changed; image payload changes mark texture resources changed. Material resource references propagate that change transitively. `_resourcePayloads` does not list environments or LUTs, but native payload claim maps refresh their stage consumers. ## Gotchas and implementation floor

### Asset-only edits and text-only transport

The accepted probe receiver decodes each String and immediately loads/diffs. It has no asset hydration callback. Its host suppresses identical authored text. An asset-only save therefore needs an explicit trigger and fresh candidate-byte preparation; resending identical text alone through the current receiver yields no byte change. Archive inspected directly at the supplied candidate SHA-256 `e7f294f5668e3f51eeb03f1180260405bf60cd0d767d6a8a97022ebeb8ab56cf`. See [probe source receipt](probe-source-receipt.json).

Existing `LutResolver`, `GltfUriResolver`, or a caller loading `readFsceneb` can reread bytes without WebSocket framing changes **if those bytes are already readable by the app at the chosen location**. A caller can supply fresh bytes on each received-text trigger. No present resolver makes the host's source directory visible inside a phone. Bundled `loadAssetBytes` and native asset fallback read the installed package, not edited host files. Host file access from the iOS app is NOT_RUN here; Android is also NOT_RUN and A142 remains reserved. Android port forwarding eventually provides network reachability, not filesystem sharing.

If source bytes exist only on the host, delivering them to the app is a new transport responsibility. The existing text-only WebSocket has no binary framing or asset association contract. An explicit app-readable file location, existing bundled fixtures for controller-only byte replacement, or the existing in-memory glTF resolver/sidecar-reader supplied by a caller are current alternatives for bounded proofs. Bundled fixtures alone do not prove external-file reload. There is no basis here to invent binary WebSocket frames, an asset graph, HTTP asset serving, revisions, reconnect, or polling.
