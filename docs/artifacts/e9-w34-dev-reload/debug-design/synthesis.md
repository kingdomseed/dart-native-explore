# W34 architecture decision after cross-judgment

No candidate is accepted as a complete production base. One factual native-particle experiment precedes public implementation. B is the single candidate to reconsider if that missing route becomes source/runtime supported; there is no combined A/B/C build.

The parent read all three candidates and the independent judgment end to end. Parent provisional A11/B12/C12 scores credited explicit uncertainty more generously than the judge's A9/B11/C10. The ranking difference is resolved by the judge's pinned-source facts, not by averaging scores: B avoids unnecessary Android attachment duplication and target rescheduling; C's standalone-per-target-view sketch would repeat color clearing and needs an explicit first/subsequent view policy. All three still lack a demonstrated live SceneKit particle route. Acknowledging that gap does not make an architecture complete.

Parent verified installed SCNParticleSystem conforms to SCNAnimatable, not SCNShadable; existing decodeParticleEmitter creates/attaches that native system and assigns particleImage. It is reachable through the existing public emitter components. SCNParticleSystem property callbacks expose simulation properties, not sampled fragment color, depth or triangle attachments. This is a necessary scene-preservation/input-access question; it does not prove all public renderer-local techniques impossible.

Parent read pinned Renderer.cpp clear/standalone sections and Engine.cpp prepare. They corroborate the two implementation conditions. B may prepopulate diagnostic surface instances before beginFrame, then choose already-prepared material references/edge ranges at screen submission. C cannot preserve current ordered multi-view target output by merely replacing each render call with standalone rendering under unchanged clearing. No production correction is applied because these are sketches, not integrated code.

Keep the converged view-owned caller direction and canonical authored capture ownership as design constraints. There is no new controller setter or authored debug schema. Prefer compressed axial depth d/(1+d) and flat magenta for semantically absent inputs if B is later selected. Catcher receiver inspection is an explicit possible debug semantic under the original W34 floor; do not commit B's extra live-footprint-access promise without need. These are prospective synthesis constraints, not an implemented public contract.

No graft closes the particle gap. Do not combine projection graphs, temporary slot selection and target/image pipelines. Do not add another particle simulation/drawer, generic registry, shader translator/fork, synchronization layer or capability fallback. Native callback data may observe the original population but cannot feed reconstructed billboards.

Next is one Prototype instrument: original SCNScene, native emitter, known mesh control, renderer-local SCNTechnique DRAW_SCENE program. First ask whether a constant diagnostic fragment overrides living particle draws when it demonstrably overrides the mesh. If that necessary premise fails, preserve the failed candidate and stop this route before broader projection/public API work. If it passes, meaningful sampled color/depth/edges and authored-target isolation still need proof in the same bounded instrument; interception alone is not completion.

Apple SCNTechnique documentation and installed header establish custom Metal scene-pass definitions and a renderer-local technique property, but do not establish native-particle shader/binding interception. Primary reference read by parent: https://developer.apple.com/documentation/scenekit/scntechnique?changes=_2_1_8 . The hook is a hypothesis for native observation, not a fact inferred from DRAW_SCENE's name.

Accepted58 remains the production-intended baseline. A142 reserved, simulator off, no device action in design. Runtime/build/test/performance remain NOT_RUN for these designs. Existing W34/T1/T2/T3/T4 scope remains unchanged.
