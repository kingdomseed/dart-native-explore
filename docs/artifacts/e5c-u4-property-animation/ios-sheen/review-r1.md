**Failure and contract:** the existing sheen modifier adds `_output.color.rgb += tint * rim;` at line2698 without changing alpha. Previously the deleted final multiplication attenuated that added RGB as well as the generated material RGB. Current line2611 keeps the added term but no longer attenuates it. For a white sheen, roughness1 and N·V=.5, the added RGB is .5 at both alpha1 and alpha0; at alpha0 it must contribute zero to ordinary alpha composition. The result is a visible rim on an otherwise fully transparent material, and excessive sheen at partial alpha.

This follows from the actual shader source and the installed SDK's contract: `SCNShadable.h:142–145` defines transparent blending as final premultiplied RGB plus `(1-alpha)*destination`; `:538–540` identifies the fragment modifier as the last shader entry point altering final color. **Owner and minimum correction:** native ordinary-material fragment construction owns this conversion. Keep the demonstrated removal of the whole-output RGB multiplication, and premultiply only the manually added sheen contribution by the effective output alpha for ordinary BLEND materials. OPAQUE/MASK behavior should retain its existing semantics. Apply the correction to the shared sheen term so uniform and textured sheen use the same rule.
